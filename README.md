# mySilversat_admin

لوحة تحكم خدمة **سلفرسات** للبث الفضائي — واجهة إدارية بالعربية (RTL) مبنية على React + TypeScript + Vite.

ما بيها شاشة تنادي الـ API مباشرة: كلشي يمرّ بـ **طبقة مستودعات** (`src/data/repositories/`) تخلّي
المكوّنات ما تعرف شكل أي راوت، والتجميع بملف واحد (`src/data/repositories/index.ts`).

## التشغيل

```bash
cp .env.example .env   # وحط عنوان الـ API بـ VITE_API_BASE
npm install
npm run dev        # http://localhost:5180
npm run build      # فحص الأنواع + بناء الإنتاج
npm run typecheck  # فحص الأنواع فقط
```

تسجيل الدخول خطوتين لأن الـ API هيك سوّاه: رقم الهاتف وكلمة المرور يجيبون رمز SMS من ست خانات
(`/auth/login`)، والرمز هو اللي يجيب التوكن (`/auth/verify-otp`). التوكن ينحفظ بـ `localStorage`
لأن عميل الـ HTTP يقراه من هناك مو من حالة React.

للأدمن رتبة — **مدير عام** أو **مدير** أو **وكيل** — تنعرض بالهيدر وبالإعدادات، بس اللوحة ما تحجب
أي شاشة على أساسها. الصلاحيات يفرضها الـ API، واللوحة تعرض جوابه.

## الباك-إند

الـ API حقيقي وشغّال، وينشر توصيفه على `/api-docs-json` (وواجهة Swagger على `/api-docs`). هذا
المرجع قبل أي تعديل على مستودع، لأن أربع سلوكيات منه ما تنفهم من أسماء الراوتات:

- **فلاتر تنقبل وتنتجاهل بصمت.** `/leagues?isActive=…` يرجّع كل الـ 1,237 صف بالحالتين، و`/matches`
  يتجاهل `isOpenForPrediction`. التصفية على هذولة تصير على الصفوف باللوحة، مو بالطلب.
- **راوتات التطبيق ترفض توكن الأدمن.** `/matches/live` و`/leagues/active` و`/matches/open-for-prediction`
  يرجّعون 401 — و401 يمسح الجلسة المخزونة، فقراءة وحدة منهن باللوحة تطلّع الموظف برّا.
- **`/ads` ياخذ الصورة ملف** بنفس طلب الحفظ (multipart)، وما عنده حقل لرابط صورة إطلاقاً.
- **سقف `limit` هو 100** على كل راوت قوائم، وتجاوزه 400 مو قصّ.

أي شي مو محسوم بالتوصيف (هل يرجع `total`؟ كيف ينقرأ `false` بالـ multipart؟) ينفحص على السيرفر
قبل ما ينبنى عليه — أغلب أخطاء هذا المستودع جت من افتراض بدل فحص.

## الشاشات

- **عام** — لوحة المعلومات
- **توقع واربح** — المباريات، التوقعات، الترتيب والنقاط، الدوريات والفرق
- **المشتركون** — المشتركون، الأجهزة، المبيعات، المخزن
- **السحوبات** — السحوبات والجوائز، الكوبونات
- **محتوى التطبيق** — سلايدر الرئيسية، الفيديوهات، الأسئلة الشائعة، الأبراج، قنوات التواصل
- **التواصل** — الإشعارات
- **النظام** — المحافظات والدول، الـ API، سجل العمليات، الإعدادات

ماكو شاشة مستقلة للباقات والأسعار ولا للوكلاء. المنتجات وفئاتها وأسعارها الأربعة تنتعدّل **جوّا
شاشة المخزن** على المستوى اللي تخصّه، لأن نفس الشجرة أصلاً تمشي عليهن — تفاصيلها بالفصل الجاي.

وشاشة **المحافظات** مو جدول: تعرض لكل محافظة سيرفرها ومنتجاتها وفئاتها ومخزنها ومشتركيها،
و«تفاصيل» تفتح كل هذا بمكان واحد مع فحص السيرفر وأسعار كل فئة.

## التنقّل

**Ctrl + K** يفتح لوحة الأوامر من أي مكان — اكتب حرفين من اسم الشاشة واضغط Enter. البحث يشمل وصف
كل شاشة مو بس اسمها، يعني «كارت» توصّلك لمخزن الكارتات. نفس الزر موجود بالهيدر لمن ما تحب
الاختصارات.

## ثلاث قواعد تحكم اللوحة

### المباريات تجي من API — ما تنضاف يدوياً

الدوريات والفرق والمباريات كلها مرآة لمزوّد خارجي. ما بيها زر «إضافة مباراة» ولا «إضافة فريق»، بس
زر **مزامنة**. الربط يصير على `externalId` تبع المزوّد، فالمزامنة الثانية تحدّث ما تكرّر.

اللي تملكه اللوحة فوق بيانات المزوّد هو قرار التوقع فقط — أي مباراة تنفتح للتوقع ومتى يقفل — والمزامنة
ما تلمس هذين الحقلين أبداً. الاستثناء الوحيد **تصحيح النتيجة يدوياً**: النقاط تنحسب على النتيجة،
فإذا المزوّد غلط تكدر تثبّت نتيجة صحيحة.

بس انتبه: التصحيح **ما ينحمى** من المزامنة — مزامنة المباشر الجاية تكدر ترجع تكتب عليه من المزوّد،
وماكو علامة بالـ API تمنعها. فإذا كنت تصحّح حتى تحتسب النقاط، احتسبها فوراً بعد الحفظ كنتيجة
نهائية. نفس التحذير مكتوب بنافذة التصحيح لهذا السبب.

إعدادات المزوّد (الدومين والمفتاح وفترة المزامنة) في شاشة **الإعدادات**.

### كل محافظة إلها مخزن كارتات

المخزن **لكل محافظة** لأن هيك يشتغل فعلاً: التجديد بالبصرة يحرق كارت بصرة. التجديد يسحب أقدم كارت
متاح (FIFO) بنفس مدة الباقة من مخزن محافظة المشترك، وإذا خلص المخزون **التجديد ينرفض** بدل ما يمدّد
اشتراك ما دفع عليه كارت. المنحة المجانية هي الطريقة الوحيدة اللي ما تسحب كارت.

الاسترجاع ما يرجّع الكارت للرف — الكارت انفعّل عند المزوّد فعلاً — فينعلّم «ملغى» ويظل بالسجل.

بس ماكو عمود محافظة لا على الكارت ولا على الدفعة: الكارت يتبع فئة، والفئة تتبع منتج، والمنتج بس هو
اللي يسمّي المحافظة. عشان هيك شاشة **المخزن** مو جدول مسطّح، هي **شجرة** تنمشي مستوى مستوى:

```
المنتجات  →  الفئات  →  الرفعات  →  الكارتات
```

المنتج هو المستوى اللي ينحمل بيه الربطان: **المحافظة** اللي هذا مخزنها، و**سيرفر الـ API** اللي
راح يفعّل كارتاتها — وكلاهما ينتعدّلون من نموذج المنتج نفسه بأي مستوى. الفئة هي اللي تحمل الأسعار
وهي مستوى المخزون الحقيقي («خلصنا» دائماً تعني فئة وحدة خلصت). الرفعة ملف كارتات واصل، وجوّاها
الكارتات.

و«منتج مع فئاته» ينشئ الاثنين بطلب واحد، لأن منتج بلا فئة ما ينباع وما يستلم كارتات.

المسار ينحفظ بالـ URL (`?product=…&category=…&batch=…`)، فزر الرجوع يطلع مستوى للفوق، والرابط
ينشارك، والتحديث يرجّعك لنفس المكان. وعدّادات كل مستوى تنحسب من عدّادات الرفعات اللي يحسبها الـ
API — يعني الشجرة كلها ثلاث قراءات، مو قراءة لكل صف.

وبما إن الفئة معروفة قبل ما تنضغط «رفع دفعة»، انلغت أكبر غلطة كانت ممكنة بالشاشة القديمة: رفع
كارتات البصرة على فئة نينوى.

### كل محافظة إلها API

كل المحافظات تشتغل على نفس البرنامج، يتغيّر بس **الدومين وAuth Key واسم المستخدم والرمز**. شاشة
**الـ API** تضيف السيرفر وتفحصه، والربط نفسه يصير **من المنتج**: كل منتج يأشّر على سيرفر واحد،
والمنتج يتبع محافظة وحدة — فسيرفر المحافظة هو اللي تأشّر عليه منتجاتها.

القاعدة المفروضة: **المحافظة تنربط بسيرفر واحد بس**. الـ API ما يكدر يفرضها لأن الربط موزّع على
المنتجات، فشاشة **المحافظات** هي اللي تكشفها: محافظة منتجاتها موزّعة على سيرفرين، أو ما تأشّر على
أي سيرفر، تنعلّم خطأ أحمر بالجدول وبالتفاصيل.

ونفس الربط هو اللي يحدّد وين يروح **الاستعلام والتجديد**: شاشة الأجهزة ما تخلّيك تنتخب السيرفر من
قائمة، تمشي السلسلة جهاز ← مشترك ← محافظة ← سيرفر. سؤال عن رسيفر ينسأل للسيرفر الغلط يرجّع جواب
واثق وغلط، وهذا أسوأ فشل ممكن بأداة دعم. التجاوز اليدوي باقي للحالة اللي السلسلة ما تنحل بيها،
ويكتب صراحةً إنه تجاوز.
